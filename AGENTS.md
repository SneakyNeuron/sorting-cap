# Sorting Cap

## Specs
This project uses Spec-Driven Development. Read `specs/mission.md`, `specs/tech-stack.md` and `specs/roadmap.md` before any work. Feature specs live in `specs/features/`. Keep specs and code in sync: when code changes a decision, update the spec in the same commit.
- Every spec deviation found while implementing (a choice the spec did not make, or a change to one it did) goes into the feature's `requirements.md` Decisions table, and into the requirement or plan text it touches, in the same commit as the code. Ticking the finished tasks in `plan.md` belongs in that commit too.
- In `validation.md`, the Understanding checks and opt-in live evaluations are recommended, not blocking. When a feature closes without them, mark each one as skipped (`- [ ] … — skipped: <reason>`) instead of leaving it silently open.
